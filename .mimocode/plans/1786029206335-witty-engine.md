# P1 Fixes: Telegram Recovery Flow + Promocode Error Messages

## Problem 1: Session deleted on transient errors during Telegram recovery

**Root cause**: `recoverRemnashopTelegramSession` (client.ts:1329-1334) has a catch-all that deletes the session on ANY error, including network timeouts and upstream 503s.

```ts
} catch (error) {
    await prisma.webSession.deleteMany({ where: { id: sessionId, userId } });
    throw error;
}
```

**Impact**: If Remnashop has a 30-second outage, all users attempting Telegram auth during that window permanently lose their sessions.

**Fix**: Classify errors before deleting:
- **Terminal errors** (ACCOUNT_MERGE_REQUIRED, ownership mismatches) → revoke session + clear cookies
- **Transient errors** (UPSTREAM_UNAVAILABLE, network, timeout) → preserve session, rethrow so user can retry

### Files to modify

1. **`src/backend/integrations/remnashop/client.ts`** — `recoverRemnashopTelegramSession` (line ~1296)
   - Replace catch-all with error classification
   - Import `isServiceErrorCode` from service-error.ts
   - Only delete session for terminal codes: ACCOUNT_MERGE_REQUIRED, ACCOUNT_MERGE_SUBSCRIPTIONS_CONFLICT
   - For all other errors: preserve session, throw error (user sees generic "try again" and can retry)

2. **`tests/integration/services/telegram-recovery-postgres.test.ts`** — add tests:
   - Test: UPSTREAM_UNAVAILABLE preserves session
   - Test: ACCOUNT_MERGE_REQUIRED revokes session
   - Test: network error preserves session

### Implementation

```ts
// In recoverRemnashopTelegramSession, replace the catch block:
} catch (error) {
    const isTerminal = error instanceof ServiceError && (
      error.code === "ACCOUNT_MERGE_REQUIRED" ||
      error.code === "ACCOUNT_MERGE_SUBSCRIPTIONS_CONFLICT"
    );
    
    if (isTerminal) {
      await prisma.webSession.updateMany({
        where: { id: sessionId, userId, revokedAt: null },
        data: { revokedAt: new Date() },
      });
    }
    
    throw error;
}
```

Key changes:
- Use `updateMany` with `revokedAt` instead of `deleteMany` (preserves audit trail)
- Only revoke on terminal errors (ACCOUNT_MERGE_REQUIRED, ACCOUNT_MERGE_SUBSCRIPTIONS_CONFLICT)
- Transient errors (UPSTREAM_UNAVAILABLE, network, timeout) preserve the session
- Always rethrow — the caller handles the redirect/error display

## Problem 2: Promocode errors show generic message

**Root cause**: `activateCabinetPromocode` (execute-command.ts:46-48) uses bare `catch {}` that discards the error.

```ts
catch {
    return { status: "error", message: "Не удалось активировать промокод." };
}
```

**Impact**: Users see "Не удалось активировать промокод" for all 14+ distinct error codes including already-activated, expired, not-found, subscription-required, etc.

**Fix**: Capture error, use `ServiceError.prodMessage` as fallback.

### Files to modify

1. **`src/backend/application/cabinet/execute-command.ts`** — all 4 catch blocks:
   - `deleteCabinetDevice` (line 17-19)
   - `deleteAllCabinetDevices` (line 26-28)
   - `reissueCabinetSubscription` (line 35-37)
   - `activateCabinetPromocode` (line 46-48)

2. **`tests/unit/backend/application-facades.test.ts`** — add tests for ServiceError propagation

### Implementation

Add a shared helper (same pattern as `manage-linked-account.ts`):

```ts
import { ServiceError } from "@/backend/errors/service-error";

function errorMessage(error: unknown, fallback: string): string {
  if (error instanceof ServiceError) {
    return error.prodMessage;
  }
  return fallback;
}
```

Then update each catch block:

```ts
// Before:
catch { return { status: "error", message: "Не удалось активировать промокод." }; }

// After:
catch (error) { return { status: "error", message: errorMessage(error, "Не удалось активировать промокод.") }; }
```

Apply to all 4 functions in execute-command.ts.
