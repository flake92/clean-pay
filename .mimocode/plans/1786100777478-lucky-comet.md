# Исправление postgres-concurrency тестов

## Контекст
CI job `postgres-concurrency` падает на `test:services`. Локально unit-тесты проходят (549), но интеграционные тесты с PostgreSQL не инициализируют реестр сервисов.

## Корневая причина

### Проблема 1: Не инициализирован реестр сервисов
Файлы `passkey-deletion-postgres.test.ts` и `telegram-recovery-postgres.test.ts` не вызывают `initServiceRegistry()` в `beforeAll`. Код вызывает `auditLog()` → `getServiceRegistry()` → падает.

### Проблема 2: Нет Redis в CI
CI job `postgres-concurrency` не имеет Redis сервиса. Если инициализировать реестр, `cacheStore` будет пытаться подключиться к `localhost:6379` и упадёт при вызове `assertRateLimit`.

## План исправления

### Шаг 1: Добавить `initServiceRegistry()` в `passkey-deletion-postgres.test.ts`
- После импорта `prisma` добавить:
```typescript
const { initServiceRegistry } = await import("@/backend/services/registry");
initServiceRegistry();
```

### Шаг 2: Добавить `initServiceRegistry()` в `telegram-recovery-postgres.test.ts`
- Аналогично, после импорта `prisma`

### Шаг 3: Добавить Redis сервис в CI job `postgres-concurrency`
- В `.github/workflows/ci.yml` добавить Redis контейнер к job `postgres-concurrency`

## Файлы для изменения
- `tests/integration/services/passkey-deletion-postgres.test.ts`
- `tests/integration/services/telegram-recovery-postgres.test.ts`
- `.github/workflows/ci.yml` (добавить Redis сервис)

## Верификация
1. `npx vitest run` — все 549 тестов зелёные
2. CI на GitHub — `postgres-concurrency` зелёный
