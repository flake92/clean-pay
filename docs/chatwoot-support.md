# Поддержка через Chatwoot

Clean Pay подключает стандартный Chatwoot Website Widget только для
авторизованного пользователя. Секрет идентификации остаётся на сервере:
браузер получает внутренний ID пользователя и готовую HMAC-подпись, но не
получает `CHATWOOT_HMAC_TOKEN`.

Новые зависимости, миграции базы данных, webhooks и изменения Chatwoot для
этого варианта не требуются.

## 1. Настройка Chatwoot

1. В Chatwoot откройте **Settings → Inboxes** и создайте либо выберите канал
   **Website**.
2. В настройках Website Inbox добавьте публичный домен Clean Pay в список
   разрешённых доменов, например `pay.example.com`.
3. Включите **Identity Validation**. Скопируйте:
   - **Website Token**;
   - **HMAC Token** из секции Identity Validation.
4. В **Settings → Custom Attributes → Contact** создайте текстовые атрибуты:
   - `clean_pay_user_id` — внутренний ID Clean Pay;
   - `telegram_id` — Telegram ID;
   - `telegram_username` — имя пользователя Telegram без `@`;
   - `subscription_context_status` — доступность данных подписки;
   - `subscription_plan`, `subscription_status`,
     `subscription_expires_at`, `subscription_is_trial` — тариф и состояние;
   - `payment_context_status` — доступность платёжных данных;
   - `last_payment_status`, `last_payment_at`, `last_payment_amount`,
     `last_payment_gateway`, `last_payment_plan` — последний платёж;
   - `recent_payments` — безопасная текстовая сводка пяти последних платежей.
5. В **Settings → Labels** создайте labels `payment_problem` и
   `subscription_expired`.

Без объявления custom attributes Chatwoot всё равно принимает их, но заранее
созданные атрибуты удобнее отображаются агенту и доступны для фильтрации.

## 2. Настройка Clean Pay

В `deploy/prod/.env` заполните все три значения:

```dotenv
CHATWOOT_BASE_URL=https://chat.example.com
CHATWOOT_WEBSITE_TOKEN=<website-token>
CHATWOOT_HMAC_TOKEN=<identity-validation-hmac-token>
```

Правила конфигурации:

- `CHATWOOT_BASE_URL` — только HTTPS origin, без завершающего пути, query и
  fragment;
- все три значения задаются вместе; если оставить все три пустыми, интеграция
  отключена;
- `CHATWOOT_HMAC_TOKEN` является серверным секретом: не добавляйте к нему
  `NEXT_PUBLIC_`, не передавайте в клиентский код и не используйте повторно как
  другой секрет Clean Pay;
- после изменения выполните обычное обновление приложения:

```bash
./deploy.sh install
```

Перед запуском production-валидатор проверит комплектность настроек, HTTPS,
формат токенов, отсутствие шаблонных и повторно использованных секретов.

## 3. Как это работает

После входа пользователя Clean Pay загружает SDK с
`https://chat.example.com/packs/js/sdk.js`, показывает плавающую кнопку и
передаёт Chatwoot:

- неизменяемый внутренний ID как основной `identifier`;
- серверную HMAC-SHA256 подпись этого ID;
- подтверждённый e-mail;
- имя пользователя;
- внутренний ID, Telegram ID и Telegram username как custom attributes;
- название, статус, срок и trial-признак текущей подписки;
- статус и безопасную сводку пяти последних синхронизированных платежей.

Неподтверждённый e-mail намеренно не отправляется: Chatwoot умеет объединять
контакты по e-mail, поэтому доверять адресу до его подтверждения небезопасно.

Контекст подписки и платежей загружается отдельным защищённым Server Action
после запуска виджета и кешируется в браузере на одну минуту. При следующем
открытии чата после истечения кеша контекст загружается заново. Это не
задерживает рендеринг кабинета: при временной ошибке Remnashop или базы платежей
базовый чат остаётся доступным, а соответствующий `*_context_status` получает
значение `unavailable`. VPN URL, payment URL, идентификаторы платёжных операций
и сырые ответы провайдеров не передаются.

Если Remnashop вернул подписку с некорректной датой окончания,
`subscription_context_status` получает значение `invalid`. Остальные поля
подписки передаются агенту как справочные, но Clean Pay не добавляет и не
снимает `subscription_expired` по недостоверной дате.

Для платежей Clean Pay читает данные и состояние их синхронизации в одной
транзакции. Если успешная синхронизация отсутствует или старше 15 минут,
`payment_context_status` получает значение `stale`: сводка остаётся доступна
агенту как справочная, но Clean Pay не добавляет и не снимает по ней
`payment_problem`.

Clean Pay управляет двумя labels диалога:

- `subscription_expired` — текущая подписка имеет статус `EXPIRED` либо её
  дата окончания прошла;
- `payment_problem` — последний платёж имеет статус `FAILED`, `CANCELED` или
  `UNKNOWN`, либо остаётся `PENDING` не менее 30 минут.

Следующая актуальная синхронизация снимает label, если проблема устранена. При
недоступном источнике label не снимается на основании неполных данных.
Для нового обращения labels повторно применяются после первого сообщения — к
этому моменту Chatwoot уже создал диалог. Все contact custom attributes
передаются вместе с подписанной командой `setUser`, без отдельного анонимного
обновления.

В Chatwoot можно создать Automation Rules по этим labels. Для каждого правила
выберите событие **Conversation Updated**, добавьте условия **Labels contains**
с нужным label и **Team is not** с целевой командой, затем действия **Assign
team** и при необходимости **Send message**. Условие по текущей команде служит
защитой от повторного срабатывания правила после назначения команды или
автоматического ответа. Так `payment_problem` можно направлять платёжной
команде, а `subscription_expired` — команде продлений. Это штатная настройка
Chatwoot и не требует API-токена или webhook Clean Pay.

При обычном выходе Clean Pay сначала сбрасывает сессию и cookies Chatwoot, а
затем завершает локальную сессию. Гостевые страницы дополнительно очищают
оставшиеся данные виджета — в том числе если сессия истекла или SDK не успел
загрузиться. Это не позволяет следующему пользователю увидеть чужую историю.

CSP автоматически разрешает только настроенный origin Chatwoot для SDK,
iframe, HTTP-запросов и WebSocket. Если настройки неполные, origin в CSP не
добавляется и виджет не загружается.

## 4. Проверка после установки

1. Войдите в Clean Pay и убедитесь, что справа появилась кнопка чата.
2. Напишите тестовое сообщение.
3. В Chatwoot откройте контакт и проверьте имя, подтверждённый e-mail,
   Telegram-атрибуты, тариф, подписку и последние платежи.
4. Создайте тестовый неуспешный платёж либо используйте тестового пользователя
   с истёкшей подпиской и проверьте соответствующий label.
5. Выйдите из Clean Pay: кнопка должна исчезнуть.
6. Войдите под другим тестовым пользователем: должен открыться его отдельный
   контакт и отдельная история.
7. Откройте страницу входа после истечения сессии и убедитесь, что виджет не
   отображается.

Если кнопка не появилась, проверьте разрешённый домен Website Inbox, включённую
Identity Validation, совпадение Website/HMAC Token, доступность
`CHATWOOT_BASE_URL` из браузера и отсутствие ошибок CSP в консоли. После смены
Website Token или HMAC Token перезапустите Clean Pay и повторно войдите.

## Что ещё не входит в интеграцию

В текущий вариант не входят объединение старых контактов при слиянии аккаунтов,
автоматическое определение `connection_problem`, серверная маршрутизация,
webhooks и управляющие действия из Chatwoot. Маршрутизацию и ответы по уже
доступным labels можно настроить штатными Automation Rules Chatwoot. Для
двусторонних операций нужен отдельный контракт событий и API с аудитом и
авторизацией; текущий виджет от него не зависит.
