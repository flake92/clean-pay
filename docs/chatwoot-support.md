# Поддержка через Chatwoot

Clean Pay подключает стандартный Chatwoot Website Widget только для
авторизованного пользователя. Секрет идентификации остаётся на сервере:
браузер получает внутренний ID пользователя и готовую HMAC-подпись, но не
получает `CHATWOOT_HMAC_TOKEN`.

Новые зависимости, миграции базы данных, webhooks и изменения Chatwoot для
этого варианта не требуются.

## 1. Настройка Chatwoot

1. В Chatwoot откройте **Settings → Inboxes** и создайте либо выберите канал
   **Website**.
2. В настройках Website Inbox добавьте публичный домен Clean Pay в список
   разрешённых доменов, например `pay.example.com`.
3. Включите **Identity Validation**. Скопируйте:
   - **Website Token**;
   - **HMAC Token** из секции Identity Validation.
4. В **Settings → Custom Attributes → Contact** создайте текстовые атрибуты:
   - `clean_pay_user_id` — внутренний ID Clean Pay;
   - `telegram_id` — Telegram ID;
   - `telegram_username` — имя пользователя Telegram без `@`.

Без объявления custom attributes Chatwoot всё равно принимает их, но заранее
созданные атрибуты удобнее отображаются агенту и доступны для фильтрации.

## 2. Настройка Clean Pay

В `deploy/prod/.env` заполните все три значения:

```dotenv
CHATWOOT_BASE_URL=https://chat.example.com
CHATWOOT_WEBSITE_TOKEN=<website-token>
CHATWOOT_HMAC_TOKEN=<identity-validation-hmac-token>
```

Правила конфигурации:

- `CHATWOOT_BASE_URL` — только HTTPS origin, без завершающего пути, query и
  fragment;
- все три значения задаются вместе; если оставить все три пустыми, интеграция
  отключена;
- `CHATWOOT_HMAC_TOKEN` является серверным секретом: не добавляйте к нему
  `NEXT_PUBLIC_`, не передавайте в клиентский код и не используйте повторно как
  другой секрет Clean Pay;
- после изменения выполните обычное обновление приложения:

```bash
./deploy.sh install
```

Перед запуском production-валидатор проверит комплектность настроек, HTTPS,
формат токенов, отсутствие шаблонных и повторно использованных секретов.

## 3. Как это работает

После входа пользователя Clean Pay загружает SDK с
`https://chat.example.com/packs/js/sdk.js`, показывает плавающую кнопку и
передаёт Chatwoot:

- неизменяемый внутренний ID как основной `identifier`;
- серверную HMAC-SHA256 подпись этого ID;
- подтверждённый e-mail;
- имя пользователя;
- внутренний ID, Telegram ID и Telegram username как custom attributes.

Неподтверждённый e-mail намеренно не отправляется: Chatwoot умеет объединять
контакты по e-mail, поэтому доверять адресу до его подтверждения небезопасно.

При обычном выходе Clean Pay сначала сбрасывает сессию и cookies Chatwoot, а
затем завершает локальную сессию. Гостевые страницы дополнительно очищают
оставшиеся данные виджета — в том числе если сессия истекла или SDK не успел
загрузиться. Это не позволяет следующему пользователю увидеть чужую историю.

CSP автоматически разрешает только настроенный origin Chatwoot для SDK,
iframe, HTTP-запросов и WebSocket. Если настройки неполные, origin в CSP не
добавляется и виджет не загружается.

## 4. Проверка после установки

1. Войдите в Clean Pay и убедитесь, что справа появилась кнопка чата.
2. Напишите тестовое сообщение.
3. В Chatwoot откройте контакт и проверьте имя, подтверждённый e-mail и три
   custom attributes.
4. Выйдите из Clean Pay: кнопка должна исчезнуть.
5. Войдите под другим тестовым пользователем: должен открыться его отдельный
   контакт и отдельная история.
6. Откройте страницу входа после истечения сессии и убедитесь, что виджет не
   отображается.

Если кнопка не появилась, проверьте разрешённый домен Website Inbox, включённую
Identity Validation, совпадение Website/HMAC Token, доступность
`CHATWOOT_BASE_URL` из браузера и отсутствие ошибок CSP в консоли. После смены
Website Token или HMAC Token перезапустите Clean Pay и повторно войдите.

## Границы базовой интеграции

В текущий вариант не входят объединение старых контактов при слиянии аккаунтов,
данные подписки и платежей, автоматические теги, командная маршрутизация,
webhooks и управляющие действия из Chatwoot. Для них нужен отдельный контракт
событий и API с аудитом и авторизацией; базовый виджет от них не зависит.
