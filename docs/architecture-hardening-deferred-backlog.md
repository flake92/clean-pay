# Отложенный backlog наблюдаемых дефектов

Этот список зафиксирован для архитектурного hardening от согласованного
baseline-коммита ветки `update-nodejs`. Перечисленные сценарии намеренно
не исправляются в этой работе: их текущее наблюдаемое поведение является частью
immutable browser/contract baseline. Исправление каждого пункта требует
отдельного продуктового решения, новых characterization-ожиданий и явного
разрешения на semantic diff.

## P0 — security contract

1. **Непроверенный JWT `sub`.** Не полагаться на непроверенный либо
   недостаточно связанный с ожидаемым владельцем subject. Отдельная работа
   должна определить issuer/audience/subject binding, fail-closed ошибки и
   обратную совместимость действующих сессий.

## P1 — auth, payments и lifecycle

2. **Потеря `redirect_to` после отмены Telegram merge.** Отмена merge может не
   вернуть пользователя к исходному сценарию. Нужна отдельная спецификация
   разрешённых redirect targets и поведения cancel/retry.
3. **Silent `EMAIL_REQUIRED`.** В одном из auth/recovery путей обязательность
   e-mail не получает самостоятельной понятной пользователю обратной связи.
   Текущие result shapes и copy в этой работе сохраняются.
4. **Logout/Chatwoot failure lifecycle.** Ошибка очистки либо завершения
   Chatwoot во время logout имеет неоднозначный lifecycle. Нужна отдельная
   политика порядка локального logout, widget reset, retry и telemetry.
5. **Chatwoot stale loader/restart.** Loader может сохранить устаревшее
   состояние после сбоя или повторного запуска. Исправление должно отдельно
   специфицировать singleton/restart state machine и смену пользователя.
6. **Смешанные валюты.** Представление либо агрегация записей разных валют
   требует продуктового правила; автоматическое суммирование/конвертация в
   рамках архитектурного рефакторинга запрещены.

## P2 — PWA и presentation fallbacks

7. **Ранний `beforeinstallprompt`.** Событие может произойти до установки
   слушателя. Нужна отдельная договорённость о времени регистрации и хранении
   deferred prompt без изменения текущего install flow в этой работе.
8. **Invalid-date fallback.** Некорректная дата имеет неоговорённое fallback-
   отображение. Новый текст или скрытие значения является пользовательским
   изменением и требует отдельного UX-решения.
9. **Maskable icon.** В manifest отсутствует отдельно проверенный maskable
   asset/safe zone. Нужен новый визуальный asset и его review; существующие
   иконки в этой работе не подменяются.

## Условие снятия пункта

Для каждого дефекта необходимы: отдельный issue/решение владельца продукта,
characterization исходного поведения, новые contract/browser tests, явный
allowlist semantic diff и проверка rollback. Нельзя обновлять существующие
baseline screenshots, чтобы скрыть изменение.
